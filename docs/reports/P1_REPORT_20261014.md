**`HarnessContextAdapter`**（`src/par/context/harness.py`），对一个已登记项目只读地给出：

## 11. 下一阶段 P2 的建议（本轮不施工）

P2 就是你说的「多模型协同架构」的核心：**任务内核**。全部在新仓库内，零外部依赖，零真实模型调用。

- **SQLite 台账**（标准库，WAL）：`tasks` `attempts` `events`（只追加）`approvals`；唯一键 `(project_id, idempotency_key)`；状态带版本号做乐观并发；只存任务事实，不存项目知识。
- **状态机**：显式转移表，机械拒绝非法跳转（`RUNNING → ACCEPTED` 禁止；`CANCELED → RUNNING` 只能新建 attempt）。完成必须同时满足终态可解析、差异在权限内、Kernel 自己跑的验证通过、审批到位，退出码 0 不算数。
- **执行层**：由 Kernel 启动进程组，超时（启动 60 秒、无输出 5 分钟、总计 20 分钟，可配）、先温和后强制终止、只杀自己启动的进程组；工作区用 fixture git 仓库，记录起始 commit 与 dirty manifest，捕获 diff。
- **用上 P1**：提交任务时把 Context Manifest 的 `digest`、`base_git_commit`、`state_revision`、`dirty_digest` 存进 attempt；执行前后对比，发现漂移就停。
- **Profile 解析**：确定性路由，主模型加备用链，任务启动时冻结配置快照；不做评分。
- **命令**：`par task submit / status / result / cancel`。
- **Gate**：至少 20 项自动测试覆盖合法与非法转换、幂等、防重复执行、审批、断点记录、异常恢复、部分写入、超时；断电式重启不丢关键事件；零真实模型调用。我会按 60 项以上去做。
