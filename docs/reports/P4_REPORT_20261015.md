## 0. 先说四件你最需要知道的事

1. **agy 已经接入、私有安装、并用真实模型调用过一次，但它还没有独立完成夹具任务。** 那次获批的写入烟测（`gemini-3.8-flash-medium`，9.3 秒）里，模型读了 `app/calc.py`，想运行 `python3 -m unittest -q`，被无头模式**自动拒绝**，随后结束了这一轮：**厂商状态 `SUCCESS`、退出码 0、答案为空、没有改任何文件**。Kernel 自己的单元检查失败，任务判为 `FAILED`（`validation`），软拒绝作为警告记在结果里——**「软拒绝被正确判断」在真实运行里得到了验证，「agy 完成夹具任务」没有。** 原因是我们的提示词叫它「让测试通过」，项目的 `AGENTS.md` 叫它「用测试命令检查」，而无头模式里命令一律被拒；Kernel 提示词里的「被拦住就停下」又让它停了。我据此加了一个通用的 `prompt_note` 钩子，让 agy 的提示词末尾（`## Environment`，计入保存与哈希）事先说明「这里没有 shell 命令，这不是被拦住，直接改文件，检查由 Kernel 代跑」。**这个调整没有被真实验证**——你批准的那一次调用已经用掉了。要达成 P4 Gate，需要你再批准一次真实调用（第 7 节 B1）。

2. **官方 FAQ 里有一条账号层面的条款风险，需要你来判断。** Google 写明：①配合第三方软件（举例 Claude Code、OpenClaw、OpenCode）使用你的 Antigravity 登录属于违反服务条款，可能导致账号被暂停或终止；②无头模式 `agy -p`「面向直接脚本与 CI」，把 `agy` **包进第三方编码代理或应用**、或自动轮换账号，在**消费者套餐下不受支持**。你的登录经 CLI 自己的日志确认是 `consumer` 类型。我们的 Runtime 是你自己的本地脚本直接调用官方 CLI，贴近「直接脚本」；但 P5 若让 Claude Desktop 通过 MCP 桥触发 agy 任务，就可能被解读为「包进第三方编码代理」。你在上一轮已回答「知悉，继续烟测」（烟测由本机脚本直接调用，不经 Claude）；**P5 之前还需要你单独决定「agy 任务能不能由 Claude Desktop 触发」**（选项见第 11 节）。我无法替你判断 Google 怎么解释。

3. **agy 的真实行为与官方文档有好几处不同，我按真实行为做了设计，而且发现你已有的 Antigravity 登录就能直接用。** 最重要的：①私有 HOME 隔离成立——`agy` 完全尊重 `HOME`，你的 `~/.gemini`（含旧 gemini 的凭据）对它不可见，每次真实探测/烟测自己的前后快照都无任何变化（事故除外，见下一条）；②登录来自**钥匙串**（对照实验：去掉我放进私有 HOME 的那条钥匙串目录符号链接，它就认不出登录），所以**没有做任何新的登录**，Runtime 没有碰过任何凭据；③未登录时 `-p /usage` 会打印 Google 登录网址并**等 60 秒**（文档说会报错退出），只有 `models` 立刻失败——登录检查因此改用 `models`；④`--print-timeout` 默认是 `0s`（文档说 5 分钟）；⑤CLI 会改写我们写的 `settings.json`，并**丢掉了 `enableTelemetry=false`**——遥测是否真的关闭**未验证**，我不再声称它关了。

4. **一件我自己造成的事故，已按你的批准还原，但你必须知道**：我的一项变异检验（M126，故意把 agy 登录计划指向你**真实的** home，用来证明测试抓得到这种错）在运行时真的改了你机器上的东西——`~` 的权限 750→700、`~/.gemini` 的权限 755→700、新建 `~/.gemini/antigravity-cli/settings.json`（Runtime 自己写的只读预设，261 字节）。它**不是产品行为**（真实运行永远用私有 HOME，已实测），而是测试工具对真实 home 的误写；两个变异检验批次各触发了一次（第一次在 2026-10-14 21:43 前后，第二次在 10-15 00:46 前后）。我在最终复查时才发现，随即停下，没有动你的文件就问了你；你选了「全部还原」，我先核对那个文件逐字节就是我们的预设、目录里只有它，再把 `~` 改回 750、`~/.gemini` 改回 755、删掉那一个文件和空目录，并核对 `~/.gemini` 的 16 个条目与我最初看到的完全一致。`~` 上多了一个 macOS 自己管理的空 `com.apple.provenance` 标记（`~/.gemini` 本来就有），我没有碰它。根因已修且验证过：私有 HOME 一律拒绝等于真实 home 的目录（先于任何创建/chmod）；变异检验在每个变异前后核对真实 home，**任何变异改动它就立刻中止整个运行**。这也意味着我之前报告里「前后快照无变化」只对「每次真实探测/烟测自己的前后」成立，不是对整个 P4 期间的担保。

**Antigravity 适配器**（`providers/antigravity.py`，约 680 行）
- 绝对路径 + Google 签名（团队 `EQHXZ8M8AV`，只收 Mach-O；脚本、别的团队、PATH 上的 `agy` 一律拒绝）；提示词作为标准输入上的一行 stream-json `user` 事件；`agy --input-format stream-json --output-format stream-json --model … --sandbox --print-timeout 24h`。
- **Worker 的 HOME 是 attempt 的私有目录**：适配器的 `prepare()` 往里写 Runtime 自己的 `settings.json`（只读任务 `strict`，写任务 `request-review`；沙箱开、不花 AI 积分、不出工作副本、没有任何允许规则、没有 API key 提供方）和一条指向钥匙串目录的**符号链接**（不是拷贝）。**链接只在 agy 运行期间存在**：子进程一结束，适配器的 `cleanup` 钩子就把它删掉，证据目录里不留指向你钥匙串的指针（有测试证明目标不受影响）。**私有 HOME 绝不能是你的真实 home**：`write_home` / `login_plan` 一开始就拒绝。

### 过程中被实测 / 测试抓到、已修复或已记录的问题（如实记录）
1. **（真实烟测）模型想跑测试被拒后「什么都不输出」**——见第 0 节第 1 条；已加 `prompt_note`（未经真实复验）、利用 `denied_actions`、统一软拒绝措辞。
2. **（实测）未登录的 `-p /usage` 会等 60 秒**：登录检查改用 `agy models`，有测试与变异检验（M144）。
3. **（实测）文档与真实不符**：`--print-timeout` 默认 `0s`；有 `--mode`/`--disable-slash-commands`/`--log-file` 等文档没列的标志；`--effort` 取值多了 `xhigh/max`；工具步骤状态有 `ERROR`；`result` 有 `denied_actions`；`--help` 打印在 stderr。完整对照见 AGY.md §11。
4. **（测试抓到）分类词汇的真 bug**：「429 Too Many Requests: rate limit exceeded」曾因含「limit exceeded」被归为**额度用尽**——那会让整个 Provider 被封到你手动清除。Kernel 全流程测试抓到，已修，并有变异检验（M132）。
5. **（变异检验抓到）我的一个测试类里有个叫 `fail` 的辅助方法，遮蔽了 `unittest.TestCase.fail`**，导致那个类里所有失败的断言悄悄通过。M133「存活」暴露了它；已改名，并新增守卫测试「测试类不得遮蔽 `TestCase` 的公开方法」（M143 验证），整个套件仅此一处。
6. **（全量测试）一次 `error`**：我的一个单元测试用的裸 Python 子进程在 shell 后台任务里继承了「忽略 SIGINT」而挂住——测试问题不是产品问题；改成子进程自己恢复默认并报告就绪，并在后台任务里复现验证。
7. **（实测）`settings.json` 被 CLI 改写，`enableTelemetry=false` 被丢掉**：遥测是否关闭未验证；适配器的持久化报告与文档都已改成「请求关闭、未验证」。
8. **（实测）每个 attempt 的私有 HOME 里 agy 留下约 13 MB**（含 12.7 MB 的 `bin/webm_encoder`、对话库、日志）——不在你的 `~/.gemini`，但长期会占盘；清理策略放到后面。
9. **（事故）变异检验 M126 误写了你的真实 home**——见第 0 节第 4 条；根因已修、已还原、已加变异检验的安全网。
