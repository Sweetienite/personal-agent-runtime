# Code of Conduct

## Our standard

Be direct, technical and respectful. This project deals with permissions, credentials and code
execution; reports about safety boundaries deserve careful, good-faith discussion even when the
answer is "by design".

Expected:

- Critique ideas and code, not people.
- Give enough context to reproduce a problem.
- Respect embargoes on security reports.
- Do not pressure maintainers to merge, publish, or weaken a safety check.

Not acceptable:

- Harassment, insults, or discriminatory language.
- Publishing someone's credentials, private paths, or unpublished vulnerability details.
- Pressing for a change that would make an unsafe default pass a test.
- Impersonating a vendor or a maintainer.

## Scope

Issues, pull requests, discussions, commit messages and any project-managed communication.

## Enforcement

The maintainer may edit or remove content and may block participation for repeated or serious
violations. For a confidential concern, use the private security contact in
[.github/SECURITY.md](.github/SECURITY.md) rather than a public issue.

This code is intentionally short; it is not a corporate policy and creates no SLA.
